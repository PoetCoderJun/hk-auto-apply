# 选岗与读 JD

用户交来的岗位范围是唯一标准。不要套用其他候选人的梯队、行业偏好或排除列表。

## 把说明编成四类规则

读完岗位范围（以及简历里能佐证的约束）后，写成一份可执行备忘，再开始搜岗：

1. **优先**：应主动用多个关键词覆盖的方向
2. **可考虑**：不是第一选择，但仍符合说明、应该投
3. **硬性排除**：标题或 JD 对上就记「不投」，不要投
4. **软性提示**：说明里写的是加分、偏好或「最好有」，不是硬性门槛。这类岗位仍可投，但要在备注里写上该提示

范围太笼统、写不成这四类时，回到 [intake.md](intake.md) 追问，不要自己补一套标准。

未得到新的指示前，不要改选岗标准。

## 从规则推出搜索词

用「优先」和「可考虑」里的职务名、职能和常见同义写法生成多个搜索词。用户的范围若是金融或商业方向，可作起点的词包括：Assistant Relationship Manager、Relationship Manager、Wealth Management、Equity Research、Investment Banking、Institutional Sales、Business Analyst、Financial Analyst、FP&A、Management Trainee、Client Success、Compliance、KYC、Fund Operations、Virtual Asset、Crypto。按当前这份规则增减，不要把这份起点词当成所有用户的默认目标。

标题预筛时注意常见串岗：财富 / MT 类关键词常会涌进保险代理和佣金制理财顾问岗；research 类常会涌进高校或临床研究助理。这些只有在用户的硬性排除里覆盖到时才丢掉。

## 读 JD

不要把标题或卡片匹配当成已经读完 JD。说明漏斗时要区分「卡片级筛掉」和「JD 级排除」，并按平台拆开。

对准备投或拿不准的 JD，先跑信号提取，再拿结果对照用户的四类规则：

```bash
python3 "$SKILL_DIR/scripts/jd_flags.py" --text "JD 全文"
```

脚本只提取机械信号，例如明确的年限要求、公司历史里的「XX 年」、粤语是硬性还是加分、是否明显实习岗。它不决定投或不投。

尤其不要把公司介绍里的「成立超过 20/50/60 年」「五年战略规划」当成候选人必须具备的年限。`jd_flags.py` 会尽量忽略这类句子；若脚本标成 ignored，就不要再用它来排除候选人。

对照规则时：

- 硬性排除成立 → 不投，备注写清触发了哪一条
- 只有软性提示 → 仍投，备注写上该提示
- 年限、语言、牌照、签证等字段，以 JD 的硬性表述和用户规则为准；简历里没有的资质不要假装有


## 把信号对照规则

先从简历估算「可以声称的全职相关年限」：默认只数简历上写明的全职工作。实习和课程项目不算全职年限，除非用户的岗位范围明确说可以算。不要把在读学位的年数当成工作年限。

然后对照 `jd_flags.py` 的输出和用户的四类规则。下面是常见情形，不是某个候选人的标准：

- 脚本标出 `required_years_min` ≥ 5，且用户把「要求 5 年及以上」列为硬性排除：不投。
- 脚本把某段年限标成 `ignored`（公司历史或战略规划）：不要用这段来排除。
- JD 要求 3 到 5 年相关经验，简历只有实习或项目：不要编造年限。若用户规则要求必须具备该经验，记不投，备注「必备相关经验不足」。
- `native_cantonese` 为真，简历没写粤语：不投。没写就不要填会粤语。
- 粤语只是 preferred / 加分：仍可投，备注里写上该软性提示。
- 标题明显是 Director / Managing Director / Executive Director 一类，且候选人明显达不到：不投，备注「显著偏高级/资深岗」。
- 只有软性提示（例如 1 年优先、牌照加分、要求立即到岗但用户给的是更晚的可入职时间）：仍投，备注写上该提示。

脚本不决定投或不投。最终以用户这份岗位范围为准。
