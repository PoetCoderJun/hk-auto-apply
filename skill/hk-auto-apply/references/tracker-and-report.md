# 跟踪表、分析报告与每日增量

## 跟踪表存在哪里

跟踪表不必写成 Notion 文档。用户可以指定下面任意一种，指定了就用那种，不要自行改成 Notion：

- 本地 Excel 工作簿（`.xlsx`），完成后交给用户下载
- [Google 表格](https://sheets.google.com)
- 飞书电子表格或多维表格
- Notion 数据库
- 用户点名的其他表格或文档

用户没指定时，默认生成一份带「平台」列的本地 Excel，并告诉他们之后可以再导出，或迁到 Google 表格、飞书、Notion 或其他地方。已经在用某张表时，接着更新那张表，不要平行再开一份，除非用户要求。

同一套字段适用于以上所有载体。投递表字段至少包括：岗位、状态（待投递 / 投递中 / 已投递 / 不投）、公司、JD 链接、备注、申请方式、地点、来源、**平台**（JobsDB / LinkedIn）、发现日期、投递日期。双平台海投时「平台」是必填项；旧行若没有这一列，要加上并把已有记录补成对应平台。

不要删除跟踪表里的探测行或重复行，除非用户明确要求。不要把整月旧帖或整个待投队列预先全部写成「待投递」；只在发现后决定不投、真正投出、或现场跳过时写表。

公开分享不是必须的。用户要求分享时，按他们选的载体给出只读链接或导出文件；未要求就保持私有。用 Notion 发布时设为「发布到网上」且仅可查看，不要打开搜索引擎收录，除非用户要求。

去重前要把跟踪表导出成 [dedup.md](dedup.md) 需要的 JSON 数组，每行至少包括 `company`、`title`、`url`、`platform`、`status`。分页或分批读出全部行。若用 Notion 且 SQL 或 query 额度用尽，改用数据源默认视图翻页，不要因此跳过去重。探测行和空链接留在表里，导出给脚本前避开它们，但不要删除。

若用 Notion，建议这样建列，缺的选项再补，不要滥建：

| 字段 | 建议类型 | 取值 |
| --- | --- | --- |
| 岗位 | title | 职位名 |
| 状态 | select 或 status | 待投递 / 投递中 / 已投递 / 不投 |
| 公司 | rich_text | |
| JD链接 | url | 规范化后的岗位页 |
| 备注 | rich_text | 跳过原因或投递确认原文 |
| 申请方式 | select | Quick apply / Apply / 外部网站 / LinkedIn |
| 地点 | rich_text | |
| 来源 | rich_text 或 select | 通常与平台相同 |
| 平台 | select | JobsDB / LinkedIn |
| 发现日期 | date | |
| 投递日期 | date | 只在已投递时填写 |

本地 Excel、Google 表格或飞书用同样的列名即可，类型按各工具的普通文本、链接和日期列处理。

## 分析报告

分析报告要写成一篇可复用的调研文档，不是只在聊天里口头总结一下。它可以是本地文档、Google 文档、飞书文档、Notion 页面，或和跟踪表放在同一套工具里，不必默认上传成 Notion。内容包括：

- 搜索用了哪些词和时间窗；[search-coverage.md](search-coverage.md) 中 `complete` / `truncated` / `deferred` 分区数量及原因（429、挑战、超时、用户暂停）；明确范围是「本次计划关键词与时间窗」，不是全站
- 各平台的漏斗数字：唯一卡片（`discovered`）、deferred 待重试数、标题匹配、成功投出、**硬规则** skipped、跨平台重复；区分 retry 事件次数与唯一 `job_id`
- 各方向目前在开的岗与判断
- 常见过滤原因
- 投递时要注意的表单填写口径

调研文档里要有单独的「平台」一节，并链到或附上跟踪表。用户要求公开分享时，再按所选载体给出只读链接或导出文件；未要求就保持私有。

## 按约定时间看新岗

首轮做完（或用户明确要先设好定时任务）之后，和用户确认日常增量检查的时间：默认是工作日早上大约 9:00、用户自己的时区，时间可以有弹性，但必须让用户知道，并可以改成他们指定的时间。若投递跑在用户自己的电脑上，明确告诉他们：到点时那台电脑需要开机并保持在线。

然后按约定时间建定时任务，任务里写清：

- 按本技能做增量检查，覆盖用户要求的平台，只处理上次之后新出现、或跟踪表里还没有的岗位
- 不要重新投已经投过的，不要把整月旧帖当新岗再扫一遍，要按 [dedup.md](dedup.md) 去重
- 用同一份选岗规则、申请表答案和跟踪表，并填上「平台」
- 有符合要求且能投的就投，并马上更新表格
- 结果发回当前这个对话；没有新的可投岗位时也发一条短消息，不要完全沉默
- 登录墙或需要用户本人操作时，马上在这个对话里叫用户接管电脑登录，不要向他们要密码

不要把候选人姓名、薪资、签证或表格链接写进通用技能文本里；这些只写进这位用户的定时任务和记忆。


## 增量定时任务正文模板

把方括号换成这次运行的实际值。不要把候选人的薪资、签证或私人联系方式写进可分享的通用技能文本；那些只写进这位用户的定时任务或记忆。

```
按 hk-auto-apply 做增量检查，覆盖用户点名的平台：[JobsDB 和/或 LinkedIn]。
工作日大约 [时间]（[用户时区]，可以在约定范围内灵活）。
只处理上次之后新出现、或跟踪表里还没有的岗位，不要把整月旧帖再扫一遍。
用同一份选岗规则备忘、同一套申请表口径和同一张跟踪表，并填写「平台」。
按 skill 里的去重规则做平台内和跨平台去重。
符合规则且能投的就投，并马上更新跟踪表。
结果发回创建本任务的那个对话；没有新的可投岗位时也发一条短消息。
登录墙或需要用户本人操作时，马上在对话里叫用户接管电脑登录，不要向他们要密码。
若投递跑在用户自己的电脑上，到点时那台电脑需要开机并保持在线。
跟踪表：[文件路径或链接]。选岗规则备忘：[路径或摘要位置]。
```
