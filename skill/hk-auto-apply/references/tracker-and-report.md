# 跟踪表、分析报告与每日增量

## 跟踪表

需要在线表格时：若用户连了 Notion，就在 Notion 里建投递表和调研文档。没连就说明可以连 Notion，并先用当前对话里的记录和可分享文档顶上。

投递表字段至少包括：岗位、状态（待投递 / 投递中 / 已投递 / 不投）、公司、JD 链接、备注、申请方式、地点、来源、**平台**（JobsDB / LinkedIn）、发现日期、投递日期。双平台海投时「平台」是必填项；旧行若没有这一列，要加上并把已有记录补成对应平台。

不要删除跟踪表里的探测行或重复行，除非用户明确要求。不要把整月旧帖预先全部写成「待投递」；只在发现、投出或跳过时写表。

## 分析报告

分析报告要写成一篇可复用的调研文档，不是只在聊天里口头总结一下。内容包括：

- 搜索用了哪些词和时间窗
- 各平台的漏斗数字：唯一卡片、标题匹配、成功投出、按原因归类的跳过、跨平台重复
- 各方向目前在开的岗与判断
- 常见过滤原因
- 投递时要注意的表单填写口径

调研文档里要有单独的「平台」一节，并链到投递表。用户要求公开分享时，再把这两页发布为只读链接；未要求就保持私有。

## 按约定时间看新岗

首轮做完（或用户明确要先设好定时任务）之后，和用户确认日常增量检查的时间：默认是工作日早上大约 9:00、用户自己的时区，时间可以有弹性，但必须让用户知道，并可以改成他们指定的时间。若投递跑在用户自己的电脑上，明确告诉他们：到点时那台电脑需要开机并保持在线。

然后按约定时间建定时任务，任务里写清：

- 按本技能做增量检查，覆盖用户要求的平台，只处理上次之后新出现、或跟踪表里还没有的岗位
- 不要重新投已经投过的，不要把整月旧帖当新岗再扫一遍，要按 [dedup.md](dedup.md) 去重
- 用同一份选岗规则、申请表答案和跟踪表，并填上「平台」
- 有符合要求且能投的就投，并马上更新表格
- 结果发回当前这个对话；没有新的可投岗位时也发一条短消息，不要完全沉默
- 登录墙或需要用户本人操作时，马上在这个对话里叫用户接管电脑登录，不要向他们要密码

不要把候选人姓名、薪资、签证或表格链接写进通用技能文本里；这些只写进这位用户的定时任务和记忆。
