# JobsDB 与 LinkedIn 香港自动投递

别人用 GitHub 链接安装本技能后，只要再交一份简历，再说清或上传岗位范围，就按这一套流程做完首轮海投、写分析报告和投递记录，再设好每个工作日早上的增量投递。也用于已经装好、用户说「开始投」「海投」「每天看新岗」的情况。

平台范围：用户点了哪个就做哪个。说 JobsDB 和 LinkedIn、两个平台都投，或说在 JobsDB 同等逻辑上加入 LinkedIn，就两边都做全量海投，并按公司加岗位去重。只点其中一个时，不要自行扩到另一个，也不要扩到用户没点名的其他求职网站。

候选人资料、选岗规则、申请表答案和跟踪表地址以当前这位用户交来的材料为准，写进记忆或定时任务里复用。不要套用其他候选人的简历、薪资或筛选标准，不要编造牌照、粤语、街道地址、身份证或额外年限。

## 1. 安装与收集资料

若用户说「请安装这个 GitHub 链接」并贴了本仓库：读仓库里 `skills/jobsdb-hk-apply/SKILL.md`，按原文名称和描述存进技能库。保存成功后，马上把下面清单告诉用户，请他们按「文件 / 信息 / 偏好」一起提供；不要只说「把简历和范围发我」就等待。用户说「开始投」「海投」或已经装好本技能时，也用同一份清单核对，缺什么补什么。

### 要请用户提供什么

**文件（必须）**

1. 简历文件：PDF 或 Word
2. 岗位范围：打出来的文字，或一份选岗说明文档。要足够解读出：优先投什么、可以考虑什么、硬性排除什么、哪些只是软性提示（仍可投，但要在备注里写上）

**信息（简历里已有的不要再问）**

- 姓名、联系电话、申请用邮箱（通常写在简历上）
- 香港工作身份或签证情况
- 期望月薪及币种（乘主要年薪时再换算）
- 预计可入职时间
- 语言能力以简历为准；没写粤语就不要写成会粤语

**偏好（必须问清，或用户已经说明过的可以不再问）**

- 要投哪些平台：只做 JobsDB、只做 LinkedIn，还是两个都投
- 符合选岗规则且能投的岗位：是直接投，还是先准备名单再让用户确认
- 在线跟踪表：若已连 Notion 就建表；是否发布为只读公开页（未说就保持私有）
- JobsDB 职业分类：按简历和选岗范围选最接近的一项；拿不准再问一次
- JobsDB 若需要注册：用用户允许的 bot 信箱，还是用户指定的邮箱。不要擅自用他们的私人邮箱
- 这次投递跑在哪里：bot 的云电脑，还是用户自己的电脑
- 日常增量检查希望在几点跑（用户自己的时区）。没说可默认工作日早上大约 9:00，但要告诉用户可以改，并让他们确认

不要向用户索要 LinkedIn 或 JobsDB 的登录密码，也不要把密码列入收集清单。登录在实际使用的那台电脑上完成：用户可以自行接管这台电脑，自己登录 LinkedIn 和/或 JobsDB；也可以让助手在这台电脑的浏览器里走登录流程。

若用户选择自己的电脑：使用期间以及定时任务触发时，那台电脑要开机并保持在线。把这一点连同他们选定的定时时间一并说清楚。

### 用户交来了但有缺失时

1. 对照上面的文件、信息、偏好三类清单逐项核对。先读简历和选岗说明，能提取的就不要再问。
2. 只追问仍然缺少的项。一次说清还缺什么，不要把已经提供的再问一遍，也不要泛泛说「请补充更多信息」。
3. 下面这些算缺失，必须追问并等用户补齐：简历文件没有或打不开；没有岗位范围，或范围太笼统，形不成「优先 / 可考虑 / 硬性排除 / 软性提示」；没说要做哪些平台；没说是直接投还是先确认；没说跑在云电脑还是自己的电脑；申请表常要的身份、期望月薪或可入职时间仍然不清。日常定时任务的时间若用户说首轮后再设，可以等到设任务时再确认；若选了自己的电脑，设任务时必须提醒他们到点要开机。不要把登录密码当成缺失项去追问。
4. 必须项未齐之前，不要开始搜岗或投递。
5. 用户补了一部分之后，再核对一遍；还缺就继续只问剩下的。全部齐了，用几句话复述你读到的候选人、平台、优先方向和硬性排除项，然后开始。

把岗位范围解读成可执行的选岗规则时，用户这份说明是唯一标准；不要用其他候选人的梯队替代它。用户已经交齐必须材料，并表达要自动海投、安装本技能后开始，或说「符合要求就直接投」时，视为已授权对符合选岗规则且能投的岗位直接投递，不要逐岗再问。如果他们只是在问怎么用、还没交材料，就先把清单发出去。

## 2. 在云电脑或自己的电脑上运行和登录

这次投递可以跑在 bot 的云电脑上，也可以跑在用户自己的电脑上。开投前问清用哪一台。如果站点拦数据中心 IP，云电脑可能打不开或频繁被验证，这时改到用户自己的电脑，或让浏览走用户的电脑网络。

若用户选择自己的电脑：使用期间那台电脑要开机并保持在线；日常定时任务触发时也要开机在线，否则这次增量检查跑不了。把这一点连同他们选定的定时时间一并说清楚。

登录发生在实际使用的那台电脑上。不要向用户索要 LinkedIn 或 JobsDB 的登录密码。按用户的选择用下面两种方式之一：

1. 用户自行接管这台电脑，自己登录 LinkedIn 和/或 JobsDB。登完再把控制交回，助手接着投递。
2. 用户让助手在这台电脑的浏览器里走登录流程。JobsDB 验证码如果发到 bot 信箱或已连接邮箱，助手自己取。出现手机 App 确认、验证码发到用户自己的设备、passkey 或必须本人操作的步骤时，把屏幕交给用户完成，不要猜验证码。

如果用户主动在聊天里发了密码，也不要写回聊天或写进通用技能文本；优先仍请他们在这台电脑上自己输入，或自行接管登录。

### JobsDB

- JobsDB 在 `hk.jobsdb.com`，由 SEEK 驱动，登录走 `login.seek.com`。求职者登录通常是无密码邮箱验证码。
- 还没有账号就先注册。邮箱优先用用户允许使用的 bot 信箱，或用户指定的邮箱。不要擅自用他们的私人邮箱去注册。
- 验证码发到 bot 信箱或已连接的邮箱时，自己去取。Google 等单点登录、passkey 或需要用户本人操作时，让用户接管这台电脑完成，登完再接着做。
- 登录后把简历上传到 JobsDB 资料，并设为对雇主可见。职业分类按简历和选岗范围选最接近的一项；拿不准再问一次。

### LinkedIn

- 登录走 `https://www.linkedin.com/login`。不要向用户要账号密码。
- 用户自行接管时，等他们在浏览器里登完再继续。用户让助手登录时，在这台电脑的浏览器打开登录页并走流程；若要求在手机 App 里点 Yes、发验证码或出现设备确认，把屏幕交给用户完成，不要猜验证码。
- 登录后确认资料姓名与候选人一致，并把这次的简历上传为 Easy Apply 使用的那份。账号里若已有旧简历，优先换成用户这次交来的那份，以免 Easy Apply 发出过期文件。
- LinkedIn 搜索可先用公开的 guest jobs 接口拆近约 30 天、香港地区的岗位卡片（`f_TPR=r2592000`，地点用香港 geoId）；遇到 429 或挑战页就改在已登录的浏览器里搜。投递本身必须在已登录会话里做。
- 慢一点操作。LinkedIn 容易限流或再次要求设备确认；遇到就停下来告诉用户，不要死循环。

需要在线表格和报告时：若用户连了 Notion，就在 Notion 里建投递表和调研文档。没连就说明可以连 Notion，并先用当前对话里的记录和可分享文档顶上。登录墙、验证码拿不到，或需要用户本人接管电脑时，马上告诉他们并等，不要假装已经投出。

## 3. 建跟踪表与报告

投递表字段至少包括：岗位、状态（待投递 / 投递中 / 已投递 / 不投）、公司、JD 链接、备注、申请方式、地点、来源、**平台**（JobsDB / LinkedIn）、发现日期、投递日期。双平台海投时「平台」是必填项；旧行若没有这一列，要加上并把已有记录补成对应平台。

分析报告要写成一篇可复用的调研文档，不是只在聊天里口头总结一下。内容包括：搜索用了哪些词和时间窗、各平台的漏斜数字（唯一卡片、标题匹配、成功投出、按原因归类的跳过、跨平台重复）、各方向目前在开的岗与判断、常见过滤原因、投递时要注意的表单填写口径。调研文档里要有单独的「平台」一节，并链到投递表。用户要求公开分享时，再把这两页发布为只读链接；未要求就保持私有。

## 4. 跨平台去重

两个平台都要全量海投，但不要重复投同一个机会：

- 同一个 JD 链接，或同一家公司加实质相同的岗位名（忽略大小写和标点；Assistant RM 与 ARM 算同一岗），若跟踪表里已是「已投递」，就不要在另一个平台再投，记成「不投」并备注「与 [JobsDB/LinkedIn] 已投递岗位重复」。
- 若表里已是「不投」且原因仍适用，也不要再投，备注「与 [JobsDB/LinkedIn] 不投记录重复」。
- 同一公司的不同岗位（例如 KYC 与 RM）不算重复，要独立按选岗规则判。

## 5. 第一阶段：存量海投

第一次使用时，把近约 30 天内看到、符合选岗规则且能投的岗都投完，不要在大约 20 份时自行停下。双平台时两边都要投完并去重。有进度和卡点都及时告诉用户，不要等全部做完再汇报。

1. 从岗位范围推出多个搜索词，在当前平台上搜近约 30 天的香港岗。JobsDB 用职位名斜杠链接搜，例如 `/Assistant-Relationship-Manager-jobs`。`keywords=...&where=All Hong Kong` 常常返回 0 条，不要当成真没有岗。
2. 金融、商业类范围可用的起始词包括：Assistant Relationship Manager、Relationship Manager、Wealth Management、Equity Research、Investment Banking、Institutional Sales、Business Analyst、Financial Analyst、FP&A、Management Trainee、Client Success、Compliance、KYC、Fund Operations、Virtual Asset、Crypto。按当前选岗规则增减，不要只搜一两个词就声称没有岗。
3. 先在平台内按岗位 ID 去重；丢掉超出大约 30 天时间窗的卡片。再按第 4 节和跟踪表做跨平台去重。
4. 先用标题和公司名做卡片级筛选：对上优先方向的留下，按选岗规则掉掉明显不符合的标题。财富 / MT 类关键词常会涌进保险代理和佣金制理财顾问岗，research 类常会涌进高校或临床研究助理，标题筛选时就要按选岗规则处理。
5. 对剩下的再读 JD。用选岗规则判硬性排除和软性提示（软性提示仍可投，但要在备注里写上）。
6. 能投的就投：JobsDB 优先 Quick Apply，LinkedIn 优先 Easy Apply / 轻松申请；其次站内简单申请。外部页简单就填，复杂就跳过。申请表用已保存的候选人答案。
7. 只有看到成功确认，才把该岗记成已投递。
8. 每发现、投出或跳过一个岗，马上更新跟踪表，并填上正确的「平台」。
9. 首轮结束后写完调研文档（含各平台一节），并把漏斜、各方向判断和投递记录发给用户。

## 6. 第二阶段：按约定时间看新岗

首轮做完（或用户明确要先设好定时任务）之后，和用户确认日常增量检查的时间：默认是工作日早上大约 9:00、用户自己的时区，时间可以有弹性，但必须让用户知道，并可以改成他们指定的时间。若投递跑在用户自己的电脑上，明确告诉他们：到点时那台电脑需要开机并保持在线。然后按约定时间建定时任务，任务里写清：

- 按本技能做增量检查，覆盖用户要求的平台，只处理上次之后新出现、或跟踪表里还没有的岗位
- 不要重新投已经投过的，不要把整月旧帖当新岗再扫一遍，要按第 4 节去重
- 用同一份选岗规则、申请表答案和跟踪表，并填上「平台」
- 有符合要求且能投的就投，并马上更新表格
- 结果发回当前这个对话；没有新的可投岗位时也发一条短消息，不要完全沉默
- 登录墙或需要用户本人操作时，马上在这个对话里叫用户接管电脑登录，不要向他们要密码

不要把候选人姓名、薪资、签证或表格链接写进通用技能文本里；这些只写进这位用户的定时任务和记忆。

## 7. 站内怎么投

### JobsDB

- Quick Apply 留在 JobsDB 站内，路径大致是 `/job/{id}/apply` → 角色要求 → 资料 → 确认 → `/job/{id}/apply/success`。成功页会出现「Your application has been sent to {公司}」。
- 不要盲目点跳到外部公司申请页的 Apply：站内可能在外部表单还没填完时就标成已申请。没有 Quick Apply 的 Private Advertiser 广告，跳过一键投递。

### LinkedIn

- Easy Apply / 轻松申请留在 LinkedIn 站内。确认页要看当前选中的简历文件名是用户这次交来的那份。看到「application sent」「已提交」「Your application was sent」之类确认，才算投出。
- 平台已显示 Applied / 已申请的，记成已投递或跳过重复，不要再点一次。
- Apply 只跳到雇主 ATS 时，看一眼，简单就填，复杂就放弃。

### 两站通用

- Apply 也可能跳到雇主 ATS（PageUp、Workday、Avature、北森、Workable、Greenhouse、Aplitrak 等）：看一眼，简单就填，复杂就放弃并记成跳过。
- 可选封面信就跳过；必填时只根据简历写一小段事实。必填字段不知道就跳过该岗并记到表里，不要填假。
- 只有看到成功确认，才把该岗记成已投递。外部 ATS 放弃算跳过，不算投出。
- 不要把标题或卡片匹配当成已读完 JD。说明漏斜时要区分「卡片级筛掉」和「JD 级排除」，并按平台拆开。
- 不要删除跟踪表里的探测行或重复行，除非用户明确要求。

## 8. 验收与交付

- 已投递：看到成功确认，表里状态为已投递，有投递日期和正确的平台。
- 跳过：表里有原因备注和平台，不要写成已投递。
- 向用户报告时要按平台拆开：唯一卡片数、标题匹配数、成功投出数、按原因归类的跳过数、跨平台重复数、跟踪表链接和调研文档链接，以及定时任务会在几点跑。若走用户自己的电脑，同时提醒他们到点需要开机。
- 没有新的可投岗位时也要说一句，不要完全沉默。

## 9. 不要做的事

- 不要在缺简历、岗位范围、平台选择、是否直接投、跑在云电脑还是自己的电脑，或申请表常要信息仍不清时猜测并开始投递。
- 不要向用户索要 LinkedIn 或 JobsDB 的登录密码，也不要把密码当成必须收集的信息。
- 不要把已经提供或简历里已有的项再问一遍，也不要在用户只交了一部分材料时沉默开始。
- 不要编造简历里没有的资质或经历。
- 没有「符合就直接投」的授权时，先准备名单再确认。登录、付款、删除数据仍要按平台安全流程处理。
- 未得到新的指示前，不要改选岗标准，也不要扩到用户没点名的求职网站。
